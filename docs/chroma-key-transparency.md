# 动态色键透明

仅作为 Pdog 原生 Alpha 请求失败后、且用户或上层工作流明确接受的回退方案。正式透明装饰默认使用接口原生 Alpha，不因 4K 编辑自动采用色键。

## 执行原则

1. 从高饱和候选色中计算与参考图可见像素的颜色距离和碰撞率，自动选择冲突最小的色键；也可用 `--key-color '#RRGGBB'` 显式指定。
2. 提示 Pdog 只在待删除背景使用均匀纯色，不得生成棋盘格、渐变、噪点或背景阴影。
3. 本地转换只抠除与画布边缘连通的近似色键区域，避免误删主体内部偶然出现的相似颜色。
4. 对抗锯齿边缘生成部分透明 Alpha，并清理半透明边缘色键污染；不得缩放或插值。
5. 图像模型可能在主体外轮廓绘制少量完全不透明的色键色像素。转换器会在与透明背景相邻的窄边界带中，按 LAB 色距识别并用最近可靠前景色去溢色；空间半径与色距同时约束，主体内部的同色内容不处理。
6. 最终必须检查 RGBA、存在透明像素且仍存在不透明主体。失败时停止，不把纯色背景图冒充透明图。存在 Alpha、转换成功或色键残留统计下降都不能替代三底色人工目检。

## 常用参数

- `--transparent-strategy auto|native|chroma-key`：`auto` 与 `native` 均要求接口原生 Alpha；只有显式指定 `chroma-key` 才进入色键流程。
- `--key-color auto|#RRGGBB`：默认动态选色。
- `--chroma-tolerance 30`：LAB 色差小于该值的边缘连通区域完全透明。
- `--chroma-feather 40`：边缘羽化与去色边范围。
- `--chroma-despill-distance 55`：边界带内识别不透明色键溢色的额外 LAB 色距。
- `--chroma-despill-radius 6`：只处理距离透明背景不超过该像素半径的色键溢色。
- `--keep-keyed`：保留 Pdog 上游返回的纯色背景原图，便于审计。

## 交付披露

明确说明实际 Pdog 档位与尺寸、动态选择的色键、透明像素比例，以及“本地仅执行色键转 Alpha 与去色边，未缩放”。放大后出现任何紫红、绿色或黄色残边即判失败，不得以三底色缩略图通过覆盖放大检查结论。
